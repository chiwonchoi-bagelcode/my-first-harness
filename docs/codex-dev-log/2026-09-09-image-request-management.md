# 이미지 원본 보관과 요청 투영

## 범위

- Esc/턴 중단은 포함하지 않았다. README·커밋·전역 설치는 변경하지 않았다.
- 원본 입력은 20 MiB, 최대 8192px/변 및 기존 16,777,216픽셀 디코딩 한도를 유지한다.
- 원본 보관과 모델 요청용 이미지를 분리했다. 기존 세션을 변환하거나 삭제하지 않는다.

## 구현

- `image-request.ts`: 원본을 프로젝트별 전역 세션 디렉터리의 `attachments/<sha256>.<format>`에 보관한다. 임시 파일을 완전히 쓴 뒤 hard link로 공개하며, 같은 해시 파일이 있으면 바이트를 확인한다. 파일 모드는 0400이며 보안 샌드박스는 아니다.
- `ImageBlock.storedPath/name`을 추가한다. 세션과 message 이벤트에는 원본 Base64와 보관 경로가 남는다. 임시 요청 이미지에만 `originalDimensions`가 추가된다.
- 공개 Anthropic 표준 해상도 계산(28px 패치 1568개, 긴 변 1568px)을 적용한다. `3456×2234 → 1372×887`, 비율 유지·확대 없음. Claude Code 비공개 내부 함수와 동일하다는 주장은 아니다.
- 요청 Base64 합계가 20 MiB를 넘으면 오래된 이미지 블록을 text 생략 안내로 바꾼다. 같은 원문으로 같은 결과를 계산하고 5 MiB 단위로 제거해 반복 요청의 앞부분 변경을 줄인다. 막 받은 이미지 때문에 이 제거 단위를 채울 수 없는 경우 새 이미지를 우선 보호한다.
- 최신 assistant 뒤의 새 이미지만으로 예산을 넘으면 명시적으로 실패한다. 아직 보지 못한 이미지를 조용히 버리지 않는다.
- `agent.ts`는 이미지 원본을 기록 전에 보관하고, 이미지 요청 투영 후에 기존 토큰 예산을 검사한다. `recorded-llm.ts`도 공통 투영을 사용해 요약·중첩 호출을 포함한다. 요약에는 최근 이미지 보호를 강제하지 않는다.
- 생략 표시는 이름·당시 원본 크기·원래 경로·보관 경로와 readImage 재열람 안내를 남긴다. 경로 없는 기존 이미지에는 가짜 경로를 만들지 않는다.
- 어댑터는 기존 text/image 변환을 그대로 사용한다. 원본 파일과 원래 messages는 투영 때문에 수정되지 않는다.

## 검증

- 실제 sharp 축소·EXIF 회전, 4 MiB 초과 원본, 합계 Base64 경계, 최신 이미지 보호, 중첩 툴 결과 위치·ID 보존을 자동 테스트한다.
- 실제 임시 파일에 보관한 뒤 원래 파일을 변경해도 보관본 재열람·세션 저장/resume가 된다. 중복 동시 보관도 확인했다.
- 모의 HTTP 응답으로 Responses/Anthropic 직렬화 및 이미지 생략·보관 경로 전달을 확인했다. 실제 모델 호출/AIProxy·Farm 20 MiB 요청 수용 여부는 이번 검증에 포함하지 않았다.
- 배포 패키지를 임시 전역 위치에 설치하고 별도 cwd의 CLI, 로컬 MCP, 이미지 첨부·저장·종료를 확인했다.

## 남는 제한

- 이미지 Base64 20 MiB 예산이지 전체 HTTP 본문의 상한은 아니다. 텍스트·툴 정의·게이트웨이 자체의 요청 제한은 별도다.
- 원본 이미지는 JSON/JSONL에도 남아 저장 용량은 계속 증가한다. 파일 정리 정책은 이번 범위가 아니다.
- 읽기 전용 파일 모드는 사용자가 실행한 임의 셸 명령에 대한 보호 경계가 아니다.
- 원래 파일 수정과 무관하게 보관 원본은 유지되지만, 보관 파일을 외부에서 삭제하면 다시 읽을 수 없다.

# 계획 제출과 사용자 검토

## 채택한 구조

- DSH의 packages/plan/plan-mode/src/index.ts를 참고해 exit_plan_mode에 Markdown 계획 전문을 받는다. DSH의 툴 설명 원문을 사용하고, plan 모드 안내에는 README의 최소 안내 원문과 우리 권한 정책에 맞는 안내를 결합했다.
- CLI/TUI는 RequestPlanReview 콜백으로 승인·수정 의견·취소를 반환한다. 기존 툴 실행 일회 승인과는 별개의 선택이다.
- 승인 시 pendingPlanExit를 설정한다. 현재 모델 응답의 나머지 툴은 여전히 plan 정책을 통과한다. 다음 스텝에서 edit로 바꾸고 UI 이벤트를 보낸다. 셸·MCP 승인 정책은 유지된다.
- 수정 요청은 오류 표시가 있는 툴 결과로 피드백을 전달하여 모델이 계획을 고쳐 재제출한다.
- 검토 취소는 기존 턴 중단 경로를 사용한다. plan을 유지하며 미응답 툴 호출 쌍을 채우고 사용자 입력으로 돌아간다.
- 계획 전문·피드백·승인은 기존 툴 호출/결과의 history와 messages에 기록한다. 별도 계획 파일이나 모드 영속 저장은 추가하지 않았다.

## UI

- CLI: y/yes 승인, 다른 텍스트는 수정 의견, 빈 Enter는 취소.
- TUI: Y 승인, N 수정 의견 입력 후 Enter 제출, Esc 취소. 긴 계획은 기존 대화 스크롤로 검토한다.
- TUI의 기존 입력 초안은 검토용 수정 의견과 분리해 유지한다.
- 계획 검토 중 일반 승인 요청을 중첩하지 않는다. 종료·중단 뒤 늦게 도착한 승인은 무효다.

## 검증

- 모의 모델로 승인 후 다음 스텝 전환, 동일 배치 쓰기 차단, 수정 의견 재전송, 취소, UI 없음, edit 호출 거부, 계획 인자 검증, 늦은 승인 무효를 확인했다.
- readline 입력 테스트와 Ink TUI 키 입력 테스트, 실제 Agent와 TUI 연결 테스트를 추가했다.
- 실제 모델 API 호출 및 실제 iTerm2 수동 검증은 하지 않았다. README는 수정하지 않았다.

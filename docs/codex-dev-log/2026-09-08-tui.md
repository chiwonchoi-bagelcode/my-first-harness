# 최소 TUI와 slash 명령 미리보기

## 실행

```sh
pnpm tui
pnpm tui haiku
node my-first-harness.ts --tui
node my-first-harness.ts haiku --tui
./dist/my-first-harness --tui
```

- `--tui`를 생략하면 기존 CLI다. 기본 모델은 계속 farm이다.
- 메인은 같은 Agent·툴·스킬·MCP·저장을 만들고 화면 연결만 바꾼다. 코어와 CLI 구현, API 변환, 프롬프트, 세션 저장 형식은 변경하지 않았다.
- main checkout에서 작업했으며 README·다른 worktree·사용자 세션은 수정하지 않았다. 커밋하지 않았다.

## 파일과 역할

- `tui.ts`: Ink/React 화면, 고정 입력창, 상태 표시, 대화 스크롤, 명령 선택, 실제 터미널의 시작/복원.
- `tui-input.ts`: 한글·이모지 단위 커서 이동/삭제와 긴 입력의 가로 표시 범위. 붙여넣은 줄바꿈은 화면에서 ↵로 표시하지만 제출 내용은 원문을 유지한다.
- `tui-session.ts`: 명령 목록, 세션과 첨부 대기열, 코어 호출, 화면 상태 구독. 명령 동작 테스트는 실제 제어 객체를 사용한다.
- `tests/fixtures/tui-demo.ts`: 임시 폴더에서 모의 LLM과 실제 코어·저장을 연결하는 수동 터미널 검증 예제. 실제 API 키나 사용자 설정을 읽지 않는다.

## 화면과 키

- 상단: 모델 선택명·세션 ID. 중간: 대화·중간 보고·툴 호출. 하단: 입력창·상태·키 안내.
- `/` 또는 `/r`처럼 명령 이름을 입력하면 현재 지원하는 명령과 사용법을 표시한다.
- ↑/↓로 선택, Enter 또는 Tab으로 입력창에 채운다. 실행하지 않는다. Enter를 다시 눌러 실행한다.
- `/attach`·`/resume`은 뒤에 공백을 채워 인자를 입력할 수 있게 한다. 이미지 미지원 모델에는 `/attach` 후보를 표시하지 않는다.
- Escape는 후보를 닫고 입력은 유지한다. PageUp/PageDown은 대화를 스크롤한다.
- 왼쪽/오른쪽, Backspace, Home/End, Ctrl+A/E/U로 기본 편집을 지원한다. 고급 편집기·Markdown 렌더링·툴 접기는 이번 범위가 아니다.
- 실행 중에는 입력창을 유지하지만 새 요청 제출은 막는다. Ctrl+C는 작업 취소만 하는 명령이 아니라 기존 CLI처럼 하네스 종료와 자원 정리를 수행한다.

## 추가한 작은 정책과 제한

- 잘못된 slash 명령과 누락된 인자는 모델에 보내지 않고 화면에 오류를 표시한다. 기존 CLI의 명령 처리 방식은 바꾸지 않았다.
- TUI는 입력 오류에도 화면을 유지한다. 다만 코어 turn 실패 후에는 미완료 호출이 있을 수 있어 다음 일반 요청을 막고 `/new` 또는 `/resume`으로 세션을 선택하도록 안내한다. 세션 복구나 미완료 호출 자동 수선은 추가하지 않았다.
- 화면에서만 툴 인자를 180자 뒤에 생략한다. Agent 입력·실행 기록·저장에는 원문을 유지한다.
- 모델·툴 출력의 ANSI 등 제어 문자는 표시할 때 제거한다. 원문 로그는 그대로다.
- 최소 40열×16줄과 대화형 터미널이 필요하다. 작은 창에서는 크기 안내를 표시하며 확장하면 복원한다.
- 대화 표시에는 현재 실행의 사용자·모델·툴 시작 기록을 사용한다. resume 화면은 요청용 messages의 텍스트를 표시하며 과거 JSONL 전체를 복구해 화면에 재생하지 않는다. 모델의 resume 컨텍스트는 기존과 동일하다.
- 명령 목록은 TUI에 명시적으로 정의했다. 향후 CLI에 새 명령을 추가하면 목록도 함께 갱신해야 한다. 공통 명령 플러그인 시스템은 만들지 않았다.

## 의존성과 빌드

- Ink 7.1.1, React, string-width, wrap-ansi를 사용한다. `.tsx` 변환 단계를 추가하지 않고 TypeScript에서 createElement로 구성한다.
- 개발 의존성: React 타입과 ink-testing-library.
- Bun 단일 실행파일에서 Ink의 선택적 react-devtools-core를 외부 패키지로 두면 런타임 import 오류가 발생했다. 이를 직접 의존성으로 포함해 번들에 넣었다. 개발 도구 연결 기능을 하네스에 추가한 것은 아니다.
- 빌드 명령·출력 위치는 기존 그대로다. 테스트용으로 만든 실행파일과 세션은 임시 폴더에만 생성했다.
- 참고: [Ink 공식 저장소](https://github.com/vadimdemedes/ink).

## 검증

- 전체 테스트 137개, strict TypeScript 검사, Bun 빌드 통과.
- 명령 필터·방향키·Enter/Tab 채우기·Escape·PageUp/Down·창 크기 변경, 한글·이모지·줄바꿈 붙여넣기, 동시 제출 차단, 첨부 소비, new/resume/compact/quit를 검사했다.
- 실제 백그라운드 셸 작업이 TUI 종료 시 정리되는지 검사했다.
- 실제 PTY에서 Node 실행의 화면·명령 선택·한글 요청·중간 보고·툴 실행·최종 답변·Ctrl+C 종료(130)와 화면 복원을 확인했다.
- 같은 TUI를 사용하는 모의 실행 예제를 Bun 실행파일로 컴파일해 저장소 밖 `/tmp`에서 실행했다. 명령 선택과 정상 quit(0), 원래 화면 복원을 확인했다.
- 실제 LLM과 공개 MCP 서버에 요청하지 않았다. 실제 모델 품질·macOS 외 플랫폼의 터미널 동작까지 검증한 것은 아니다.

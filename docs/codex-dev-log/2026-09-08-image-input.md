# 사용자 이미지 첨부와 readImage

## 작업 위치

- 사용자 지시에 따라 `/Users/choechiwon/my-first-harness`, `main`에서 구현했다.
- 처음 다른 worktree에서 읽기만 했으며 그곳에는 파일을 수정하지 않았다.
- 커밋·병합·README 수정·기존 세션 삭제는 하지 않았다.

## 실행 흐름

1. `/attach /path/to/image.png`가 이미지를 읽고 다음 입력용 배열에 보관한다.
2. 다음 일반 입력이 `turn(session, input, images)`로 전달된다. 여러 번 attach하면 여러 장을 함께 보낸다.
3. 모델이 요청한 `readImage`도 같은 `loadImage()`를 사용하지만, 반환값은 해당 호출 ID의 툴 결과에 들어간다.
4. Responses는 `input_image` data URL, Anthropic은 `image.source`의 base64로 변환한다. 별도 이미지 분석용 LLM 요청은 없다.
5. 다음 정상 step에서 같은 모델이 이미지를 받는다.

## 최소 구현의 선택과 제한

- 공통 사용자 content는 텍스트 또는 이미지 블록 배열이다. 툴 content는 기존 텍스트 툴을 유지하기 위해 `string | ContentBlock[]`다.
- PNG만 지원한다. 한 장 4 MiB 이하, 가로·세로 각각 4096픽셀 이하. 요청에 포함되는 모든 이미지 원본 바이트 합계는 8 MiB 이하다.
- 확장자가 아닌 PNG 시그니처·IHDR·끝의 IEND 및 치수를 확인한다. 로컬에서 완전한 픽셀 디코딩·CRC 검증·리사이즈는 하지 않는다. 손상된 픽셀 데이터는 API에서 거절될 수 있다.
- 파일을 읽을 때 크기를 제한하고 특수 파일은 거절한다. 일반적인 공백 포함 경로, 감싼 따옴표, `~/`를 지원한다. 셸 명령이나 셸 이스케이프 문법을 실행하지 않는다.
- 새 첨부는 다음 일반 입력 한 번에 소비한다. `/new`·`/resume`는 보내지 않은 첨부를 비운다. 첨부 오류는 CLI를 종료하지 않는다. 아직 보내지 않은 첨부는 저장하지 않는다.
- 선택한 adapter의 `supportsImages`가 참일 때만 readImage를 등록한다. Farm/Luna/Haiku 구성은 활성화했다. 레거시 Chat Completions 어댑터는 텍스트 전용으로 유지하며 이미지를 누락하지 않고 거절한다.
- 새로운 이미지 툴 결과가 합계 한도를 넘으면 해당 호출에 오류 결과를 돌려줘 대화가 과대 이미지로 오염되지 않게 한다.
- 세션·원문 실행 로그에 이미지 Base64를 직접 보존한다. 원본 파일이 나중에 변경되거나 없어져도 resume가 가능하지만 세션 및 요청 로그의 디스크 사용량은 늘어난다. 별도 attachment 저장소나 중복 제거는 구현하지 않았다.
- 모델 요청 실패 시에도 현재 세션을 저장하도록 turn의 공통 오류 경로에 저장을 모았다. 별도 자동 재시도는 없다.

## 컨텍스트와 압축

- 긴 툴 결과를 줄일 때 텍스트만 자르고 이미지 블록은 그대로 유지한다.
- 문자 수 기반 임시 기준에서 Base64 문자열 길이는 제외한다. 이미지당 4,000자의 고정 가중치를 사용하며 실제 제공자의 토큰 계산이나 비용 추정이 아니다.
- 마지막 assistant 이후 들어온 이미지는 아직 주 모델이 보지 않았으므로 해당 step 직전 자동 압축을 미룬다. 이미지 토큰까지 포함한 엄밀한 예산 관리는 별도 과제다.
- 요약 JSON에서는 이미지를 번호·경로·치수로 대체하고, 같은 번호를 붙인 실제 이미지 블록들을 요약 요청에 함께 보낸다. Base64를 텍스트로 요약시키지 않는다.
- 압축 성공 이후의 요청용 messages에는 기존 정책대로 요약만 남는다. 원본 이미지는 이전 원문 로그에 남지만 자동 재조회 기능은 없다.
- MCP가 반환하는 이미지 블록의 전달은 이번 범위가 아니며 기존 처리를 변경하지 않았다.

## 검증

- `pnpm test`: 112개 통과. 실제 메인의 turn과 CLI 명령 루프를 추출한 테스트도 포함한다.
- `pnpm --package=typescript dlx tsc --noEmit --strict`: 통과.
- `pnpm build`: 통과. 출력은 `dist/my-first-harness`다.
- `pnpm test:images`: 실제 Farm + GPT-5.6 Luna에서 HTTP 요청 3회 모두 200 및 결과 검증 통과.
  - 테스트가 만든 첫 PNG의 색을 사용자 첨부로 확인.
  - 모델이 두 번째 PNG에 readImage를 요청.
  - 실제 파일 읽기 후 이미지 결과를 전송하여 다른 색을 맞히는지 확인.
  - 도중 메시지 JSON 저장/복원도 통과.
- 실호출에는 임시 생성한 단색 이미지 외 개인 파일·사용자 세션을 보내지 않았다. 임시 테스트 파일은 정리했다.
- Anthropic은 요청 형식 모의 테스트만 통과했다. AIProxy Luna/Haiku의 실제 이미지 호출이나 브라우저 화면 작업 전체를 검증한 것은 아니다.
- 실제 이미지 요약 호출은 실행하지 않았다. 요약 테스트는 실제 이미지 블록을 올바르게 전달하는지 모의 응답으로 검증했다.

## 후속 수정: 이미지 원본 경로 안내

- Haiku 실사용에서 화면 속 예시 경로를 실제 첨부 경로로 오인했다. 기존 어댑터가 이미지의 path를 모델에게 전달하지 않은 점을 보완했다.
- Responses와 Anthropic에서 이미지 바로 앞에 원본 경로 텍스트를 붙인다. 사용자 첨부와 readImage 결과 모두 적용되며 시스템 지침에는 넣지 않는다.
- 전송 시점에만 추가하므로 세션 원본은 변경하지 않고 반복 요청·resume에서도 안내가 누적되지 않는다.
- 경로는 JSON 문자열로 표시하며, 이미지가 읽힌 뒤 파일은 바뀌거나 삭제됐을 수 있음을 함께 알린다.
- 요청 본문 모의 테스트로 두 API의 첨부·툴 결과·반복 전송을 검사했다. 이번 후속 수정에서는 실제 API 호출을 하지 않았다.
- 후속 수정 후 전체 테스트 113개, strict 타입 검사, Bun 빌드가 통과했다.

# 세션 원문과 모델용 대화 분리

## 구현

- `history`: 사용자/assistant/툴 메시지 원문을 누적한다. 압축으로 변경하지 않는다.
- `messages`: 모델용 현재 대화다. 새 메시지는 양쪽에 기록하고 압축은 이 배열만 교체한다.
- `context-manager.ts`: 메시지 기록, 크기 검사, 압축 적용. 첫 system 메시지는 보존한다.
- `llm.ts`: 기존 gpt-4o Chat Completions 요청을 공유하고 `summarize()`를 추가했다. API/provider 전환은 하지 않았다.
- 요약 요청에는 툴을 보내지 않는다. 현재 대화를 JSON 텍스트로 전달하고 목표/제약/완료 상태/확인된 결과/미해결 문제를 보존하도록 지시한다.
- 두 번째 압축부터는 이전 요약과 새 대화를 요약한다. 전체 history를 다시 요약하지 않는다.
- 매 step의 일반 모델 호출 전에 대화 JSON 길이가 60,000자 이상이면 압축한다. 이전 step의 모든 툴 결과가 기록된 뒤이며, 미완료 호출이 있으면 압축을 거절한다.
- `/compact`로 수동 압축할 수 있다. 첫 구현은 최근 원문 구간을 따로 보존하지 않고 대화 전체를 요약한다.
- 압축 직전/직후 세션을 저장한다. 저장/resume은 기존 전체 JSON 저장 함수를 사용한다.

## 범위와 제한

- 60,000자는 JavaScript 문자열 길이 기준이며 정확한 token 계산이 아니다. 시스템/스킬/툴 정의는 제외된다. 전체 모델 입력 한도 보장은 후속 과제다.
- 매우 큰 단일 툴 결과는 요약 요청 자체의 한도를 넘을 수 있다. 청크 요약과 툴 출력 절단은 아직 없다.
- 비어 있거나 잘린 요약, 기존 대화보다 길어진 요약은 적용하지 않는다. 실패 시 오류로 실행이 중단되며, 직전에 저장한 원문과 현재 대화는 남는다. 자동 재시도는 없다.
- 압축 요약은 messages에만 저장한다. 요약 API 요청/응답과 사용량까지 기록하는 전체 이벤트 로그는 아니다.
- 기존 세션 포맷(history 없음)의 마이그레이션은 사용자 방침대로 구현하지 않았다. 새 세션에서 사용한다.
- 기존 툴 인자 검증은 유지했다. README는 수정하지 않았다.

## 검증

- `pnpm test`: 10개 통과. 원본 보존, 임계치, 재압축, 실패 시 상태 유지, 여러 툴 결과의 완료 경계, 저장/resume, 요약 요청 형식 등을 검증했다.
- `pnpm --package=typescript dlx tsc --noEmit`: 통과. TypeScript는 임시 실행했으며 프로젝트 의존성에 추가하지 않았다.
- Node CLI 시작 및 `/quit`: 통과.
- 합성 테트리스 작업 기록으로 실제 기존 API 요약 1회 성공. 원본 history 보존도 검증했다. 사용자 실제 대화/파일을 테스트 요청에 사용하지 않았다.
- `git diff --check`: 통과.

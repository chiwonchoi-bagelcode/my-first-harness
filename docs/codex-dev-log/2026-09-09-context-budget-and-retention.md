# 요청 토큰 예산과 최근 기록 보존

작업 위치: `/Users/choechiwon/my-first-harness`, `main`. README와 기존 세션 파일은 변경하지 않았다.

## 구현 범위

- `token-budget.ts`: 로컬 휴리스틱으로 시스템(스킬·작업 폴더 포함), 툴 정의, 메시지, 이미지의 요청 크기를 추정한다. ASCII 4자당 1토큰, 비ASCII code point당 2토큰, 이미지 장당 4,000토큰이다. 이미지 Base64는 세지 않는다. assistant는 공통 내용과 원본 replay 중 큰 추정치를 사용해 중복 합산은 피하면서 비공개 재전송 상태도 반영한다. 정확한 tokenizer나 시각 토큰 산식이 아니다.
- 압축 기준은 `contextWindow - reservedOutputTokens - safetyMarginTokens`. 실제 usage 비교, 자동 보정, 토큰 계산 API, 토크나이저 의존성은 추가하지 않았다. 캐시 적중량을 추정 입력에서 빼지 않는다.
- `LLMAdapter.contextBudget`을 모델 선택 시 전달하고 기록 래퍼에서도 유지한다. 커스텀 어댑터의 미지정 정책은 명시적인 200K 운영 예산이다.
- 과거 구간만 요약하고 최근 토큰 예산만큼의 메시지는 원문으로 남긴다. 보존 경계에 걸린 복수 툴 호출/결과는 통째로 보존한다. 남긴 assistant replay와 이미지는 그대로 유지한다. JSONL 원문은 변경하지 않는다.
- DSH의 항목별 요약 지침을 참고해 목표, 실제 검증 근거, 파일, 오류, 미완료 작업, 현재 진행, 다음 행동을 요구한다. 형식이나 사실의 진실성을 자동으로 보장하는 검증기는 아니다. 기존 독립 요약 요청 형식과 2,048 출력 설정은 유지했다. 캐시 prefix 재사용 및 제공자 전용 compaction은 이번 범위 밖이다.
- 자동 압축은 긴 툴 결과 정리 → 재측정 → 필요하면 요약 한 번 → 재측정 순서다. 이후에도 초과하면 명시적으로 오류를 반환하고 스냅샷을 보존한다. 무한 요약 재시도나 원문 강제 삭제는 없다.
- 짧은 대화는 `/compact`에서도 보존 예산 안에 들어가면 요약하지 않는다. UI에 이 이유를 표시한다. 기존 전후 문자 수 로그/화면 표시는 진단용으로 유지했으며 압축 판단에는 사용하지 않는다.
- 요약 대기 중 메시지 배열 교체/추가가 감지되면 적용하지 않는다. 동시 실행을 지원하는 새 스케줄러는 추가하지 않았다.

## 연결별 정책과 근거

| 연결 | 컨텍스트/운영 예산 | 출력 예약 | 안전 여유 | 압축 시작 | 최근 보존 |
|---|---:|---:|---:|---:|---:|
| Farm Luna | 200,000 | 32,000 | 40,000 | 128,000 | 32,000 |
| AIProxy Luna | 1,050,000 | 128,000 | 210,000 | 712,000 | 168,000 |
| AIProxy Haiku | 200,000 | 32,000 | 40,000 | 128,000 | 32,000 |

- [Luna 공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.6-luna): 1,050,000 context, 128,000 max output. AIProxy 자체의 더 낮은 제한은 확인되지 않았으며 필요하면 연결 정책을 낮춰야 한다.
- [Anthropic 모델 문서](https://platform.claude.com/docs/en/models/overview): Haiku 4.5 200K context, 64K max output. 현재 어댑터의 요청 출력 설정 32K를 예약한다.
- [Farm README](https://github.com/project-bakery/bakery-codex-farm): `gh api .../readme`로 확인. Codex OAuth 경로이며 `max_output_tokens`를 제거한다. Farm의 실제 context 상한이 문서에 없어 200K는 확인된 제공자 한도가 아니라 보수적으로 선택한 하네스 운영 예산이다. 출력 예약 역시 실제 cap 강제가 아니다.
- 사용자의 추가 요청으로 최근 보존량은 DSH 기본값 `retainRatio: 0.16`을 적용했다. `floor(contextWindow * retainRatio)`로 계산하며 출력 예약을 뺀 입력 예산의 16%가 아니다. Farm은 설정된 운영 예산 기준이다. 툴 호출 쌍 경계에 따라 실제 보존량은 더 커질 수 있다. 압축 시작 기준은 변경하지 않았다.
- 안전 여유 20%와 최근 보존 비율은 성능 최적값을 보장하지 않는다. 긴 턴에서는 최신 사용자 요청도 보존 구간 밖으로 나갈 수 있으므로 최근 원문 보존이 모든 목표 기억을 보장하지 않는다.

## 검증

- 전체 `pnpm test`: 179개 통과. 모델/API 응답은 모의이며 사용자 키를 사용한 실제 LLM 호출은 하지 않았다. 기존 테스트에는 로컬 stdio MCP·자식 프로세스 실행이 포함된다.
- `pnpm exec tsc --noEmit`, `pnpm run build`, `git diff --check` 통과. 빌드는 기존 `dist/` 설정을 사용한다.
- 합성 요청 768,500자(텍스트와 툴 정의), 워밍업 후 30회 휴리스틱 계산 평균 약 2.9ms. 전체 스텝 시간이나 정확도 측정이 아닌 로컬 계산 비용 참고치다.
- 최근 기록/이미지/replay 보존, 복수 툴 경계, 요청 헤더 크기, 모델별 정책, 요약 중 추가, 예산 초과 종료를 검증했다.
- 기존 `tests/harness.test.ts`의 테스트 툴 두 곳에 누락된 `description`을 추가해 타입 검사를 복구했다. 실행 동작은 바꾸지 않았다.

## 남은 한계

휴리스틱과 안전 여유는 실제 제공자 한도를 보장하지 않는다. 요약의 환각을 자동 검증하지 않으며, 이미지 최신 N장 정책/다운샘플링, 요약 요청 캐시 최적화, 실제 API overflow 복구는 추가하지 않았다. 이 변경은 기존 세션 저장 형식을 바꾸지 않는다.

# 출력 한도에서 작업 분할을 요청하는 복구

- `max-tokens`일 때 잘린 응답은 기존 `model-response` 원본 로그·사용량에만 보존한다. `messages`에 추가하거나 그 응답의 툴을 실행하지 않는다.
- 같은 턴에 하네스 피드백을 user 역할로 추가한다. 직전 응답의 툴은 실행되지 않았고, 앞선 성공 작업은 유효하며, 생성량을 줄여 작업·파일을 나누거나 부분 편집을 사용하라고 안내한다. 전체 덮어쓰기로 일부 내용만 저장하지 말라는 주의도 포함한다.
- 피드백 메시지의 JSONL 이벤트에는 `source: "harness"`를 붙여 실제 사용자 입력과 구분한다. 세션의 메시지 본문에도 하네스 피드백임을 표시한다.
- 복구는 턴당 최대 2회다. 성공한 툴 스텝이 끼어도 횟수를 초기화하지 않는다. 다음 턴은 새 카운터를 사용한다.
- 한도 소진·다른 오류는 기존 실패 처리로 전달한다. CLI/TUI의 일반 오류 후 세션 재개 정책은 변경하지 않았다.
- CLI/TUI에는 복구 횟수와 진행 안내를 표시한다. 파일을 어떻게 나눌지는 모델이 결정하며 특정 툴 순서를 강제하지 않는다.
- Anthropic 어댑터는 max_tokens를 블록 검사보다 먼저 확인한다. 불완전한 tool_use 인자·thinking 서명 때문에 복구 전에 파싱 오류가 나는 것을 방지하며, 원본 HTTP 응답과 사용량은 observer가 먼저 기록한다.
- 출력 한도 자동 증가는 추가하지 않았다. Haiku의 32,000 기본값을 유지하며, 이번 복구는 작업용 코어 루프에만 적용한다. 요약·다른 LLM에게 묻기에는 별도 복구를 추가하지 않았다.
- 검증: 빌드 및 테스트 159개 통과. 모의 HTTP를 통한 실패→피드백→작은 툴 호출→성공, 기존 성공 툴의 중복 실행 방지, 잘린 replay 제외, 원본·사용량 보존, 2회 제한과 다음 턴 초기화, CLI/TUI 안내를 확인했다. 실제 유료 모델이 작업을 분할하는 품질은 이번 테스트 범위가 아니다.

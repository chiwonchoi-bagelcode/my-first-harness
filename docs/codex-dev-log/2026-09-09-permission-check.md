# 권한 검사 첫 단계

- 작업 경로: `/Users/choechiwon/my-first-harness`. README·세션 형식은 변경하지 않는다.
- `permissions.ts`: 툴 이름·선택적 인자 조건에 따라 deny → ask → allow 순서로 판단한다. 일치 규칙이 없으면 명시한 defaultDecision을 적용한다.
- `ToolManager.execute`: JSON/스키마 검증 후 실제 execute 직전에 권한을 검사한다. 내장·MCP·ToolSearch 모두 같은 경로를 사용한다.
- `AgentOptions.permissions`와 `requestApproval`로 정책 및 화면과 독립적인 승인 콜백을 주입한다. 모드 설정과는 독립적이다.
- 기본값은 기존 동작을 유지하는 allow-all. 승인 화면, 권한 전환 명령, plan/edit 모드, 정책 저장, 경로 해석 및 OS 샌드박스는 이번 범위에 포함하지 않았다. 따라서 기본 앱의 실행 권한은 아직 제한되지 않는다.
- ask는 명시적 true만 일회 승인한다. 승인자 없음·거부·승인 함수 오류는 실행하지 않는다. 승인 UI가 연결되면 AbortSignal로 화면도 닫도록 구현해야 한다.
- 승인 대기 중 중단은 콜백이 응답하지 않아도 대기를 종료한다. 툴 해제·교체·비활성화도 실행 직전에 재확인한다. 규칙·승인 콜백에는 인자 사본을 전달한다.
- 셸 명령의 실제 효과나 원격 MCP의 부작용을 판별·격리하는 기능은 아니다. 인자 조건은 현재 코드로 제공하는 함수이며 자동으로 안전한 경로 검사를 수행하지 않는다.
- 검증: 새 모의 테스트 7개 포함 전체 206개 통과, 타입 검사·빌드·diff 공백 검사 통과. 외부 모델·MCP 호출 없음.

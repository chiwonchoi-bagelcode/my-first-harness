# AGENTS.md와 MCP ToolSearch

## 범위

- 현재 worktree에서 구현. README와 기존 세션 파일은 수정·삭제하지 않는다.
- 작업 폴더 바로 아래 AGENTS.md만 새 세션 생성 시 읽는다. 전역·상위·중첩 탐색과 경로별 rules는 미구현.
- 프로젝트 지침은 Session.projectInstructions에 보관하고 요청의 대화 앞에 별도 user 메시지로 조립한다. session.messages에 넣지 않으므로 압축·툴 결과 축약 대상이 아니다.
- CLI/TUI의 /reload-instructions가 다시 읽고 저장하며 변경 이벤트를 기록한다. 파일이 없으면 빈 지침, 다른 파일 오류는 오류로 전달한다. 시작 시 작은 지침 파일 하나만 읽도록 동기 파일 읽기를 사용했다.
- resume는 저장한 지침을 복원한다. 디스크의 최신 내용은 명시적 재로딩 또는 새 세션에서 적용한다. compact는 지침을 재로딩하지 않는다.
- 저장 형식은 version 3. 구형 형식 변환은 추가하지 않으며 이전 파일은 보존한다.

## MCP 점진적 공개

- MCP 여부는 이름이 아닌 mcp: 소유권으로 판단한다. 내장 툴은 계속 공개한다.
- 시스템에 활성 MCP 이름 목록을 안내하고 ToolSearch를 제공한다. 설명·인자 전체는 검색한 MCP만 다음 요청의 tools에 넣는다.
- ToolSearch는 인터넷 설치나 실제 도구 실행이 아니다. 이름·설명에서 공백으로 나눈 키워드를 OR 검색하고 이름 일치에 가중치를 주어 최대 5개를 공개한다. 의미 검색·번역은 하지 않으므로 정확한 이름/영어 키워드 사용을 안내한다.
- 발견한 이름은 Session.discoveredTools에 저장하여 resume에서 복원하고 새 세션에는 전파하지 않는다. 검색 상태는 압축 뒤에도 유지한다.
- 비활성화·해제된 도구는 검색·모델 정의에서 제외된다. ToolSearch도 관리 목록에서 끌 수 있다. ToolSearch 이름은 예약한다.
- 모델용 정의를 이름순으로 정렬한다. 제공자 전용 tool_reference/defer_loading을 쓰지 않으므로 검색 후 tools 변경은 캐시를 무효화할 수 있다. 네이티브 지연 로딩과 캐시 특성이 같지 않다.
- 검색된 툴을 자동으로 다시 숨기는 정책, 일반 툴 전체의 지연 로딩, plan/edit 모드는 추가하지 않는다.

## 검증

- 모의 모델로 검색 → 정의 공개 → 실행 흐름, 별도 세션 격리, 비활성화, 검색 인자·결과 수 제한 검사.
- 임시 AGENTS.md로 시작 스냅샷·압축 제외·저장/resume·TUI 재로딩·삭제 후 빈 지침 검사.
- 실제 CLI 프로세스에 /reload-instructions를 입력하는 회귀 테스트 추가.
- 외부 MCP 연결 및 유료 모델의 검색 판단 품질은 이 테스트에 포함하지 않는다.
- 최종 검증: 테스트 190개 통과, TypeScript 타입 검사·빌드·git diff --check 통과.

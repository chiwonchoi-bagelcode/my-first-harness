# 문자열 교체 기반 파일 부분 수정

- `tools/filesystem.ts`에 `editTextFile({ path, oldText, newText })`을 등록했다. 기존 등록 경로를 사용하므로 메인 루프와 어댑터는 변경하지 않았다.
- 여러 줄 원문을 공백·줄바꿈까지 정확히 검색한다. 일치가 한 곳일 때만 해당 구간을 새 문자열로 교체한다. 빈 `newText`는 부분 삭제다.
- 빈 원문, 불일치, 중복(겹친 일치 포함)은 쓰기 전에 거부한다. 기존 ToolManager가 오류를 모델용 결과로 반환한다. `replaceAll`이나 정규식·유사 일치는 추가하지 않았다.
- 모델은 변경 구간만 보내지만 디스크에는 조립된 전체 문자열을 기존 `writeFile`로 쓴다. 동시 편집 잠금·원자적 저장·백업·롤백은 이번 범위가 아니다.
- 테스트는 실제 임시 파일로 여러 줄 교체, CRLF·유니코드 보존, 부분 삭제, 달러 문자열 그대로 삽입, 거부 시 원문 보존, 파일 없음과 스키마 검증을 확인한다.
- 실제 turn 테스트에서 모의 모델이 중복 오류를 받은 뒤 주변 코드를 포함해 재호출하고 성공하는 흐름과 tool-end 기록을 검증했다.
- `pnpm test`: 108개 통과. 엄격 타입 검사, `git diff --check`, `pnpm build` 통과. 실제 API 호출은 하지 않았다.
- README·사용자 세션·실제 키 파일은 변경하지 않았다. 커밋과 병합은 수행하지 않았다.
